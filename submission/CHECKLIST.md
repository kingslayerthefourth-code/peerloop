# Submission checklist

## Prepared before the event

- [x] User approved the product, $0 budget, individual entry, and handoff roles.
- [x] Requirements, interface sketches, behavior, and acceptance cases recorded.
- [x] Event sources and conflicting closing times recorded.
- [x] Devpost draft, storyboard, development disclosure, and judge guide prepared.
- [x] No application source or executable tests created before the approved build start.
- [x] Scheduled continuation confirmed by the app: Fridays at noon, beginning October 30, 2026, Asia/Dubai.

## Build and release — Codex

- [ ] Recheck the event rules at build start; preserve preparation disclosure.
- [ ] Implement the approved features during the event.
- [ ] Complete and record the verification plan.
- [ ] Check actual code and dependencies for accidental secrets or private records.
- [ ] Create the public source repository and GitHub Pages deployment.
- [ ] Verify repository, demo, and project-path refresh while signed out.
- [ ] Capture desktop, mobile, Arabic, and plan screenshots from the working app.
- [ ] Record and verify a real 90–120 second demo with readable captions.
- [ ] Provide the final video file, subtitle file, and accessible hosted link if connected access permits.
- [ ] Replace future-tense draft claims with accurate release behavior and evidence.
- [ ] Finalize tools, credits, pre-event work, and AI disclosure.
- [ ] Update the judge walkthrough to match the release.
- [ ] Hand off all verified URLs, artifact paths, source commit, results, and remaining user actions.

## Review and entry — entrant

Target **November 28, 2026, at 8 p.m. Asia/Dubai**, before both published closing times.

- [ ] Connect any account needed for publication or video upload.
- [ ] Review the finished application and explanation; be able to answer questions honestly.
- [ ] Verify the existing eligibility details are accurate without changing them to fit an event.
- [ ] Join the event and complete required consent with guardian support if required.
- [ ] Enter the final project name, explanation, public links, tools, AI disclosure, and individual team identity.
- [ ] Explicitly opt in to CSC award consideration after reviewing the terms.
- [ ] Open the video, demo, and repository links as a signed-out viewer.
- [ ] Click Submit and verify the event's project page shows **Submitted**.
- [ ] Retain the confirmation URL and screenshot.
- [ ] Keep the submitted repository, site, and video accessible through judging; preserve the exact release used for the entry.
- [ ] Complete any organizer follow-up or prize paperwork personally.
